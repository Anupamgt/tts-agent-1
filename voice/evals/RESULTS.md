# Deskie evaluation results

Generated by `python evals/report.py` from the raw files in `evals/results/` and `tests/`.

## Key findings

- **Phone line (8 kHz, μ-law)**: Gnani Prisma v2.5 averages 25.7% WER across Hindi, Tamil and Kannada, against 56.9% for OpenAI whisper-1, so **55% fewer word errors**.
- **Phone + waiting-room babble (10 dB SNR)**: Gnani Prisma v2.5 averages 35.3% WER across Hindi, Tamil and Kannada, against 77.7% for OpenAI whisper-1, so **55% fewer word errors**.
- Hindi over a real-sounding phone line: Prisma v2.5 makes 10.3% word errors, against 34.3% for whisper-1.
- Prisma v3.0 `indic-auto` picks the right language by itself 95.1% of the time. That lets one phone number serve Hindi, Tamil and Kannada callers with no IVR menu.
- Trade-off we found: when the language is known in advance, Prisma v2.5 is more accurate than v3.0 on phone audio (25.7% vs 31.9% mean WER). Deskie therefore uses v2.5 for single-language lines and v3.0 `indic-auto` for multilingual ones (`GNANI_STT_MODEL`).

## How to read these numbers

- whisper-1 is a widely used general-purpose baseline. It is not the strongest Indic system: specialised open models (for example AI4Bharat's IndicConformer) are not in this table, and we make no claim against them.
- 25 FLEURS test utterances per language per condition, the same clips for every system. FLEURS is read speech, and the phone and noise conditions are simulated (8 kHz μ-law, 300–3400 Hz, babble at 10 dB SNR).
- The agent suite is our own (14 scenarios, 3 trials each), built on the τ-bench pass^k method. It is not the public τ-bench task set.
- Tamil/Kannada WER is high for every system partly because these languages build long compound words, so one wrong suffix costs a whole word. CER is the fairer view there.
