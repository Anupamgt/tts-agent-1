# Bolna agent configuration (buildathon)

One Bolna conversation agent that calls the backend's tools (decision D-34 in `docs/decision-log.md`). The design goal is that the model never becomes the source of a fact: every time, day, fee, status and amount comes from a tool, and the backend refuses anything unsafe whatever the model says.

| File | Paste into Bolna as |
|---|---|
| `welcome-message.txt` | Agent welcome message. It is fixed text, so the AI and recording disclosure is never generated by the model |
| `system-prompt.txt` | Agent prompt, 4,096 tokens (o200k_base, the GPT-4o tokenizer; about 4,935 with cl100k_base). Variables `{clinic_name}`, `{call_id}`, `{patient_count}` come from `user_data` on the session mint (PRD section 6) |
| `functions.json` | Custom functions, one per backend tool (21). Replace `PUBLIC_BASE` with `$PUBLIC_BASE_URL` and `Bearer TOKEN` with `Bearer $BOLNA_TOOL_TOKEN` in Bolna only; never commit real values |

Regenerate and check after any change to the prompt or the tools:

```bash
python3 agent/build_functions.py   # writes functions.json from the spec in the script
python3 agent/check_agent.py       # 91 static checks (incl. the token budget); exit 1 on failure
```

**Token budget.** The prompt is sent on every model turn, so it is capped at 4,096 tokens (o200k_base) and `check_agent.py` fails above that (it skips the check if `tiktoken` is not installed). Before adding a sentence, check whether an R-rule already covers it; the flows refer to the rules and fixed lines instead of restating them. The 21 function definitions in `functions.json` are a further ~5,900 tokens per turn and are the next place to trim if latency needs it.

`check_agent.py` fails if: a backend tool has no function or a function has no tool; a function sends a parameter the backend never reads; the prompt names a tool, value or template that does not exist; the prompt or welcome message contains a rupee amount, a clinic time, a doctor or patient name, or any long number other than 112, 108 and 14416; a fixed line is missing its English or Hindi version; or `functions.json` holds a real URL or token.

## How the prompt limits wrong answers

- **Facts only from tools (R2, R3).** The model speaks each tool's `say` sentence word for word, or translates it faithfully for Hindi callers. The prompt holds no fees, hours, doctors or windows, and the checker keeps it that way.
- **Success only on `ok: true` (R4).** The model may not say booked, cancelled, sent or refunded unless the tool returned success.
- **Fixed lines (word for word, English and Hindi):** emergency, self-harm, medical question, refill, arrival window, payment secrets, not a person, instructions, other language, cannot check, abuse warning.
- **No retry of a write (R12)**; a failed booking is followed by `get_booking_status`.
- **The backend enforces what the prompt cannot guarantee:** verification before any patient read, no foreign `patient_id`, fee consent before a fee booking, doctor-only refill decisions, refund amounts from the clinic's rule, Indian numbers only.

Tool sentences were checked for the same standard in this change (`api/tests/test_runtime.py::test_spoken_facts_are_true`):

- every window label now carries its day ("today, 5:30–6:00 pm", "tomorrow, …", "Friday 31 October, …"), so the model never works out a weekday;
- a cash booking no longer says a UPI link will be sent;
- a schedule-only delay estimate says "I do not have a live update" instead of "on time" (flow 04 T8b, gold `G-RS-007`);
- `send_sms` fills each template with the real visit, doctor and patient id (it used to put the clinic name in every slot), needs a `booking_id` for visit messages, and refuses templates it cannot fill.
